# 2026-10-24 Windows 发布版启动崩溃

## 定位

发布候选的单元测试和短时进程存活检查通过后，真实 Windows 客户端在打开既有页面
时发生 `0xc0000005`。原生转储与同源 AOT 符号将栈定位到
`RenderDocument.performLayout`，被读取的寄存器值等于 Dart 线程的空对象地址。
生成代码在布局循环之前读取了空选区的 focus 字段。JIT widget tests 没有复现该路径。

渲染后端对照未改变崩溃；真实 DPAPI 往返与既有偏好读取通过。保留原工具链和
渲染后端，没有更改 Windows、显卡、密钥保护或其他项目的设置。转储可能包含账户
数据，仅存放在本机私有诊断目录，不提交或上传。

## 修复与门禁

- 在进入布局循环前，将选区解析成非空的节点编号和偏移量。无选区或范围选区没有
  布局光标；循环只读取标量，代码块的自动滚动仍受当前光标节点与移动状态约束。
- 保留布局缓存、代码高亮复用及折叠规则。渲染库从 5,742 行降至 5,739 行，棘轮
  同步收紧，不增加预算或豁免。
- 添加无选区、折叠选区、正反向范围选区的解析测试。与原折叠测试合计 32 项通过。
- 同一份用户数据的原生发布候选在修复后显示真实页面，并持续运行超过 30 秒。
- 安装器检查增加首帧收据：必须在 30 秒内真正产生 Flutter 首帧，再存活 10 秒。
  收据仅由检查进程设置的环境变量启用；正常运行不生成文件。进程存在不再等同
  于界面可以使用。

底层优化器的触发条件尚未作为上游问题确认；此处记录实际异常栈、空对象证据与
有针对性的布局修复。正式安装器首帧门禁及四项业务验收已完成，见
[0.13.66 验收记录](release-0.13.66-validation.md)。
