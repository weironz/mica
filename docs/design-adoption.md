# 设计稿采纳记录(docs/design/ 01–19)

用户用 claude design 出了一版 19 屏设计稿(`docs/design/知识库软件开发协作/`),指示是
「参考做一版,**不能看了他的设计,漏掉了我们自己的功能**」。这份文档记采纳结论:
哪些照做了、哪些**故意不照做**及理由、哪些需要后端。

逐屏比对由四个只读分析子代理完成(04+05 / 06+08+09 / 10+13+14 / 15+16+17+18),
每屏都产出「设计稿要什么 / 代码现在是什么 / 差异清单 / 冲突 / 设计稿漏掉的现有功能」。

## 读这份稿子前必须知道的三件事

### 1. `docs/design/.../CLAUDE.md` 有两条**错误前提**,照字面执行会删功能

- 「**没有实时协作功能**,不要在设计里出现「团队成员」等入口」——**错**。工作区成员 +
  4 个可分配角色(`workspaces.rs:616`)、presence 光标(`_PresenceBar`)、分享角色、
  真实的 commenter 角色 + 评论 API(`comments.rs:130`)全都在跑。设计稿**自己也自相
  矛盾**:10 画了带头像/邮箱/角色的成员列表,11 就叫「实时协作」还画了 presence 条。
  这是整个设计目录里最危险的一行,当真会删掉成员、角色、presence、评论四套东西。
- 「**登录时选定本地/云端模式,进入后只有一个视角**」——半对。两个世界始终并存
  (`_workspaceEntries` 合并两边,运行时可切),设置面板的 tab 本身随世界增减。设计稿
  12 也自相矛盾:它同时画了「云端」和「本地设备」两组。用户已明确决定**保留两个世界**
  (「本地云不合并成单视角」)。13 工作区迁移这一屏在「只有一个视角」的前提下根本不存在。

### 2. `clients/` 那份代码快照已删除(2026-08-26)

`docs/design/.../clients/mica_flutter/lib/` 里曾有一份代码快照(5 个文件,588 KB),
是设计宿主按 `github.md` 的 `path:` 拉下来的。**已经删掉了。**

这一节原来的结论是「它旧了,下次导设计上下文前**先刷新它**」。没刷。它停在
2026-07-27,到删除那天:

| 文件 | 快照 | 实际 | 落后 |
|---|---|---|---|
| `main.dart` | 6094 行 | 11710 行 | **5616 行(48%)** |
| `ui/dialogs.dart` | 1701 行 | 5561 行 | 3860 行 |
| `editor/editor.dart` | 5019 行 | 6874 行 | 1855 行 |

它早于 `status_kit.dart`、`EmptyState`→`MicaEmptyState` 适配、评论面板、工作区切换器
改版。**设计稿漏掉大量已有功能,几乎可以肯定就是因为设计时读的是这份快照。**

所以是删掉,而不是再刷一次:**一份要靠人记得手动刷新、而实际没人刷的快照,比没有更糟**
—— 它看起来像代码事实,读它的人不会先去核对日期,而它已经造成过一次实际损害。需要代码
上下文时**直接读仓库**(`clients/mica_flutter/lib/`),那份永远是新的。

附带好处:仓库根跑 `flutter analyze` 不再扫到那份副本(它 import `dart:ui` /
`package:flutter/*`,却不在任何 pubspec 之下,只会吐一堆 `uri_does_not_exist`),
也不再有人可能改错那个 `main.dart`。

### 4. 19 屏现已全部覆盖(补齐过程本身值得记)

一度只覆盖了 15 屏:四个分析代理跑 04+05 / 06+08+09 / 10+13+14 / 15+16+17+18(12 屏),
加上先做的 02、03 和横切的 19。**01、07、11、12 曾经从未进过分析范围**,而当时这份文档
读起来像是"都看过了"。01 补做、07/11/12 补分析之后才真正齐。

教训不在于漏了四屏,而在于**分工时按"派了几个代理"记进度,而不是按"覆盖了哪几屏"**。

### 5. 07 这一屏证明了「设计稿在追代码」

07 的文案有相当一部分是从代码的 l10n **逐字复制**的(离线徽标那句、忘记密码那四句、
`上云…`/`转为本地副本…`、`N 人正在编辑`),它甚至在注释里写了 `editor.dart:5633`、
`main.dart:_BacklinksPanel` 这样的代码位置。而它画的设置 nav 是**分组之前**的扁平七行。

也就是说这份稿子有一部分不是"设计提要求",是"设计在记录已经做完的东西"——这是第 2 条
(代码快照过时)的又一个实证。读到与代码冲突的地方,先怀疑稿子旧了。

  (`DefaultTextEditingShortcuts` 映射成 move-caret-to-start/end),`CallbackShortcuts`
  解决不了(它是 `Focus.onKeyEvent`,而 onKeyEvent 从**最内层**焦点节点往外跑,焦点就在
  TextField 里);可行解是把 `Shortcuts` 插在 TextField 和 app **之间** —— 比默认映射表
  更靠内,先赢得查找。`↵` 走 `onSubmitted`,在更外层劫持 Enter 会连输入法确认一起吞。
  ②高亮**必须大小写不敏感**才能对上服务端 `ILIKE`,否则真命中会渲染成"一个字都没标"的
  行,读起来像误报;匹配一律 `indexOf` 不用正则(搜 `50%`/`a.b`/`(` 必须按字面)。
- **08 时间线分组**:今天/更早分组 + 相对时间(`15:08` / 「昨天 22:03」 / 「7 月 14 日」)

  服务端发 UTC(`…Z`),拿原始 parse 去和 `DateTime.now()` 比,会把傍晚存的版本在大半个
  地球上归进「更早」——而它明明还是今天。分组按**日历天**不按经过小时数(00:30 和 23:30
  相差 23 小时但都是今天,这才是人说的"今天")。顺手删掉了因此失去调用点的 `_formatTime`。
  另:测试里的分组用例刻意用**不带 `Z`** 的时间戳 —— 混进 UTC 串会让期望的日历天取决于
  跑测试的机器时区(CST 下绿、UTC-8 下红),时区转换单独一个用例覆盖。

- **06 剩余外观 + tooltip 位置修复**:600 宽、输入框尾部 `esc` chip、footer 的

  ↑↓/↵ 等于承诺一批不干活的键)。footer 右侧刻意是**页内查找**而不是设计稿的
  「全局搜索 ⌘⇧F」:后者正是打开这个对话框的快捷键(自我指涉),而且 Windows 优先的
  产品不该显示 mac 字形。键帽字体走 `kMonoFont` —— `'monospace'` 在 web 上不解析,
  那正是键位提示会悄悄退化成比例字体、从而不再像键的地方。
  同时修掉上次真机留下的疑点:`_paintTooltip` 把气泡放在 `anchor.top - h - 4` 而
  **top 完全没有 clamp**,代码块贴着视口上沿时气泡就画到可见区外(高亮出现、气泡不出现,
  读起来像"tooltip 坏了")。几何抽进 `chrome_layout.dart` 的 `tooltipRect`(9 测),
  判据必须是 **paint 时的裁剪区**而不是 RenderBox 的 `size` —— 后者高度是整个**文档**,
  拿它判断"上面还有空间"是在跟文档顶部比,不是跟用户看得见的顶部比。
- **清空回收站**(需要后端那批的第一项):`DELETE /api/workspaces/{id}/trash` —— 集合上的
  DELETE 表示清空,成员上的仍是 purge 单个子树。**一条语句、不需要递归 CTE**(扔文件夹时
  `delete_view` 已把整棵子树标 `is_deleted`,所以"所有 is_deleted 的行"本身就是闭包),

  是 no-op。客户端 footer 按钮走已验证过的 `showDestructiveConfirm`,**本地模式为 null 所以
  按钮不存在**(on-device store 无批量清空,本地仍可一行行删)。
  ⚠️ **这个功能在服务端部署前是坏的**:路由不存在时客户端会拿到 405 并把原始错误显示在
  对话框里。它和 `icon` 写入、`BadRequestCode` 一样,属于"必须发版才生效"的那批。

  承诺离线可用。

  写着「avatar + remote caret share one per connection」,但 `_PresenceBar` 自己**复制了
  一份**六色调色板,并按协作者在列表里的**下标**取色,而远端光标走
  `presenceColor(connectionId)`(哈希)。同一个人两种颜色;而且只要你是唯一的协作者,
  头像**永远**是第一个色。删掉那份复制、改用早就存在的 `PresenceUser.color`(5 测)。
  这是 `docs/lessons.md` 双表示红线的又一例:两份同值字面量 + 两套取色规则。

## 故意不做(及理由)

| 设计稿要求 | 为什么不做 |
|---|---|
| 16「同步与存储」三个开关(自动同步 / 仅 Wi-Fi / 离线可用) | 三个都没有对应功能也没有产品含义:同步是无条件的,本地镜像是无条件的,这是桌面应用没有计费流量概念。做等于凭空发明三个持久化偏好 + 三种同步行为 |
| 16「通知」 | 全仓库没有通知子系统 |
| 16「外观与主题」 | 没有 `ThemeMode`/`darkTheme`,暗色模式目前只是提案 |
| 16「版本历史」作为设置面板 | 版本历史是**按页**的(页面 ⋯ 菜单),不是全局设置 |
| 15 拖拽导入 | 需要新依赖(`desktop_drop`)→ 要走 CLAUDE.md 豁免;或手写两套原生层。**且绝不能先上「拖到这里」的文案再说没接** |
| 09 回收站 footer「图片下次回收时清理」 | 项目里**没有**图片 GC job。确认框承诺一个不存在的回收器,正是 19 存在要防的事 |
| 06 footer「全局搜索 ⌘⇧F」 | 那就是打开这个对话框的快捷键,自我指涉;且 Windows 优先的产品不该显示 mac 字形 |
| 08 逐字符内联 diff | 现有是块级 diff。内联要在自绘渲染器里加一种新 mark + 文本 differ,属渲染机制变更(CLAUDE.md #3),另立项目 |
| 08 每行「{n} 处改动」 | 历史列表按设计只返回元数据,每行算改动数 = N 次全量拉取 + N 次解码。只对选中项算,或不做 |
| 08「当前」pill 打在最新快照上 | 自动快照按节奏抓,最新**快照** ≠ 实时文档。改叫「最新版本」,或只在预览态等于实时态时才显示 |
| 10 footer「保存」 | 现在重命名有自己的保存、成员操作即时生效。对话框级「保存」意味着攒 diff + 回滚路径,不值当 |
| 13 方向切换 tab | 方向由你在哪一行开菜单决定(本地行只有上云,云端行只有转本地),tab 暗示能保持主体翻转方向,而主体本身就是「一个本地或云端工作区」 |

> 取消**停在页边界**,不是中断任务:硬杀可能留下一个已创建但内容只写了一半的文档,而
> "下一页开头"是导入器本来就知道怎么待着的状态。
> **不回滚**,而且如实报告已经导入了多少 —— 撤销一次"导入到已有工作区"意味着删掉用户
> 可能已经打开甚至编辑过的行;一次看得见、自己能删的部分导入,比一个替你删东西的回滚
> 安全。导入到**新**工作区的情况,用户一步就能把那个工作区删掉。
> 状态由**标志**而不是返回值决定:取消的运行返回 `Ok`(它是干净停下的),只看返回值会把
> 它报成 `done`,等于宣称整个压缩包都进来了。
> 解压和规划发生在循环之前、不可中断——那几秒里按取消,会在到达第一页时生效。

> 「跳过」有一个**精确定义**,不是估计:非 Markdown 条目是**懒上传**的(只有页面真的引用
> 才传),所以 `plan.files` 减去 `uploaded` 就是压缩包带进来、却没有任何页面指向的那批 ——
> 导出的残留、Notion 数据库页旁边的 `.csv`、一张没人用的截图。它们此前是**静默**丢弃的,
> 只写进 `tracing::warn!`。
> 列表**有上限**(50)但计数是真的:病态压缩包(比如塞了 node_modules)否则会在每次轮询里
> 甩几千条路径;而只报「50 个」会掩盖实际丢了 4000 个,所以 `skipped_total` 单独报。

> 导出 meta 报的是**三个数**而不是一个"总大小":归档是 zip,Markdown 压得狠、图片几乎
> 压不动,所以由原始字节推出的「约 X MB」对文字型账号会错得离谱、对图片型账号才大致对
> —— **误差取决于用户自己的内容的数字,比不给数字更糟**。图片在真实归档里是主导项且字节
> 精确,所以只报它,并且文案说的是"图片约",不是"下载大小"。
> 体积只算**仍被引用**的 blob(`unreferenced_since IS NULL`):没被引用的正等着 GC 清扫,
> 不会出现在归档里。

> `page_count` 的口径必须和客户端 `countPages` 一致(**不数文件夹、不数回收站**):侧栏
> 切换器对**当前**工作区的计数来自已加载的 view 树,列表端点喂的是**其它**工作区 ——
> 同一个工作区两处给出不同的数,比不给数更糟。为此把列表 SQL 提成
> `LIST_WORKSPACES_SQL` 常量,测试断言的就是生产跑的那一条,而不是另一份会漂的副本。
>
> 客户端把 `pageCount == 0` 当**"不知道"**而不是"空":本地工作区、单工作区响应、旧服务端
> 都会是 0,两者在这里区分不了,所以 0 不显示 —— 而不是宣称一个从没被数过的工作区是空的。

## 一条要守住的边界:失败文案按 code 走,不按 message 匹配

云端导入失败原本把服务端的英文句子(`no markdown pages found in the archive`)直接塞进
红条给用户看。`ApiException` 自己的文档注释早就写着「服务端的 *message* 不是应该给人看
的东西」,但当时只有 `statusCode` 可用,而 400 又区分不出具体原因。

**不要用匹配 message 文本来补这个洞**——那是双表示(`docs/lessons.md` 的红线):服务端
改一句措辞,客户端就静默地不再翻译,而且没有任何测试会红。做法是服务端给具体 code:

- `ApiError::BadRequestCode(&'static str, String)`(`crates/infra/src/error.rs`)——
  仍是 400,`message` 不变(老客户端无感),但错误体的 `code` 从通用 `bad_request`
  变成具体的 `import_no_markdown`。
- `ApiException.code`(`api/models.dart`)+ 中央 `_decode` 解析一次。
- `_apiMessage(error)` 只对**用户能采取行动**的 code 给译文,其余一律回落到原始 message
  —— 含糊的「出错了」比难看但真实的句子更糟,给没搞清楚的失败编友好文案就是在撒谎。

加新 variant 时 `cargo check` 会点出所有穷尽 match(这次抓到了 `ws.rs:error_code`
这处我原本不知道的),这是把它做成 enum variant 而不是加个可选字段的收益。
