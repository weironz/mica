# 设计稿采纳记录(docs/design/ 01–19)

用户用 claude design 出了一版 19 屏设计稿(`docs/design/知识库软件开发协作/`),指示是
「参考做一版,**不能看了他的设计,漏掉了我们自己的功能**」。这份文档记采纳结论:
哪些照做了、哪些**故意不照做**及理由、哪些需要后端。

逐屏比对由四个只读分析子代理完成(04+05 / 06+08+09 / 10+13+14 / 15+16+17+18),
每屏都产出「设计稿要什么 / 代码现在是什么 / 差异清单 / 冲突 / 设计稿漏掉的现有功能」。

## 读这份稿子前必须知道的三件事

### 1. `docs/design/.../CLAUDE.md` 有两条**错误前提**,照字面执行会删功能

- 「**没有实时协作功能**,不要在设计里出现「团队成员」等入口」——**错**。工作区成员 +
  4 个可分配角色(`workspaces.rs:616`)、presence 光标(`_PresenceBar`)、分享角色、
  真实的 commenter 角色 + 评论 API(`comments.rs:130`)全都在跑。设计稿**自己也自相
  矛盾**:10 画了带头像/邮箱/角色的成员列表,11 就叫「实时协作」还画了 presence 条。
  这是整个设计目录里最危险的一行,当真会删掉成员、角色、presence、评论四套东西。
- 「**登录时选定本地/云端模式,进入后只有一个视角**」——半对。两个世界始终并存
  (`_workspaceEntries` 合并两边,运行时可切),设置面板的 tab 本身随世界增减。设计稿
  12 也自相矛盾:它同时画了「云端」和「本地设备」两组。用户已明确决定**保留两个世界**
  (「本地云不合并成单视角」)。13 工作区迁移这一屏在「只有一个视角」的前提下根本不存在。

### 2. `clients/` 那份代码快照是**旧的**,不要当代码事实读

`docs/design/.../clients/mica_flutter/lib/` 里有一份代码快照,严重滞后:

| 文件 | 快照 | 实际 |
|---|---|---|
| `main.dart` | 6094 行 | 8881 行 |
| `ui/dialogs.dart` | 1701 行 | 2889 行 |

它早于 `status_kit.dart`、`EmptyState`→`MicaEmptyState` 适配、评论面板、工作区切换器
改版。**设计稿漏掉大量已有功能,几乎可以肯定就是因为设计时读的是这份快照。**
下次导设计上下文前先刷新它。

- **06 搜索**:键盘 ↑↓ 选结果 + `↵` 打开 + 结果计数 + 命中高亮(纯逻辑进

  (`DefaultTextEditingShortcuts` 映射成 move-caret-to-start/end),`CallbackShortcuts`
  解决不了(它是 `Focus.onKeyEvent`,而 onKeyEvent 从**最内层**焦点节点往外跑,焦点就在
  TextField 里);可行解是把 `Shortcuts` 插在 TextField 和 app **之间** —— 比默认映射表
  更靠内,先赢得查找。`↵` 走 `onSubmitted`,在更外层劫持 Enter 会连输入法确认一起吞。
  ②高亮**必须大小写不敏感**才能对上服务端 `ILIKE`,否则真命中会渲染成"一个字都没标"的
  行,读起来像误报;匹配一律 `indexOf` 不用正则(搜 `50%`/`a.b`/`(` 必须按字面)。
- **08 时间线分组**:今天/更早分组 + 相对时间(`15:08` / 「昨天 22:03」 / 「7 月 14 日」)

  服务端发 UTC(`…Z`),拿原始 parse 去和 `DateTime.now()` 比,会把傍晚存的版本在大半个
  地球上归进「更早」——而它明明还是今天。分组按**日历天**不按经过小时数(00:30 和 23:30
  相差 23 小时但都是今天,这才是人说的"今天")。顺手删掉了因此失去调用点的 `_formatTime`。
  另:测试里的分组用例刻意用**不带 `Z`** 的时间戳 —— 混进 UTC 串会让期望的日历天取决于
  跑测试的机器时区(CST 下绿、UTC-8 下红),时区转换单独一个用例覆盖。
- **各屏卡片化**:五处 section 标题换成 eyebrow(12/600/0.6 字距、muted,原来是和自己
  所辖内容等重的 18px 蓝图标标题)、数据 tab 换成虚线**选择区** + 带边框导出行 + 带图标

- **06 剩余外观 + tooltip 位置修复**:600 宽、输入框尾部 `esc` chip、footer 的

  ↑↓/↵ 等于承诺一批不干活的键)。footer 右侧刻意是**页内查找**而不是设计稿的
  「全局搜索 ⌘⇧F」:后者正是打开这个对话框的快捷键(自我指涉),而且 Windows 优先的
  产品不该显示 mac 字形。键帽字体走 `kMonoFont` —— `'monospace'` 在 web 上不解析,
  那正是键位提示会悄悄退化成比例字体、从而不再像键的地方。
  同时修掉上次真机留下的疑点:`_paintTooltip` 把气泡放在 `anchor.top - h - 4` 而
  **top 完全没有 clamp**,代码块贴着视口上沿时气泡就画到可见区外(高亮出现、气泡不出现,
  读起来像"tooltip 坏了")。几何抽进 `chrome_layout.dart` 的 `tooltipRect`(9 测),
  判据必须是 **paint 时的裁剪区**而不是 RenderBox 的 `size` —— 后者高度是整个**文档**,
  拿它判断"上面还有空间"是在跟文档顶部比,不是跟用户看得见的顶部比。

## 一条要守住的边界:失败文案按 code 走,不按 message 匹配

云端导入失败原本把服务端的英文句子(`no markdown pages found in the archive`)直接塞进
红条给用户看。`ApiException` 自己的文档注释早就写着「服务端的 *message* 不是应该给人看
的东西」,但当时只有 `statusCode` 可用,而 400 又区分不出具体原因。

**不要用匹配 message 文本来补这个洞**——那是双表示(`docs/lessons.md` 的红线):服务端
改一句措辞,客户端就静默地不再翻译,而且没有任何测试会红。做法是服务端给具体 code:

- `ApiError::BadRequestCode(&'static str, String)`(`crates/infra/src/error.rs`)——
  仍是 400,`message` 不变(老客户端无感),但错误体的 `code` 从通用 `bad_request`
  变成具体的 `import_no_markdown`。
- `ApiException.code`(`api/models.dart`)+ 中央 `_decode` 解析一次。
- `_apiMessage(error)` 只对**用户能采取行动**的 code 给译文,其余一律回落到原始 message
  —— 含糊的「出错了」比难看但真实的句子更糟,给没搞清楚的失败编友好文案就是在撒谎。

加新 variant 时 `cargo check` 会点出所有穷尽 match(这次抓到了 `ws.rs:error_code`
这处我原本不知道的),这是把它做成 enum variant 而不是加个可选字段的收益。

## 真机实测结论(2026-07-27,Windows release 构建)

widget 测试结构上覆盖不到的几项(它们都是 `part of main.dart` 的私有类)在真机上逐个点过:

**验证通过**

- 回收站「永久删除」弹确认(标题带页面名、正文写清子页面/版本历史/评论一起删),点
  「取消」后列表**完全不变**。这是原来一键就执行的操作。
- 本地模式搜索:输入框禁用 + 「本地工作区还不支持搜索」+ 说明 + 指向页内 Ctrl+F。
  原来输入任何字都答「没有找到与「x」匹配的内容」。

  重命名(本地真的能用)保留。
