# 界面与字体观感改造（Windows 桌面优先）

状态：**第 0–2 阶段已完成**（2026-11-12）；用户已选择字体方案 D。第 3–4 阶段待实施，第 5 阶段默认不做。原生跑图发现的既有 Material 诊断单独记录在第 11 节，不计为原生自动化通过。每阶段独立提交、独立验收。

> **读这份文档的规则**
> - 标「已核实」的是读代码或计算得到的事实；标「待测」的是推断，**必须先按第 3 节测量再动手**，不许把推断当事实写进提交说明。
> - 标「Notion 参考值」的数字来自记忆，只作方向参考；Mica 的取值以本文第 5、6 节的表为准，不要自己再去"对齐 Notion"。
> - 本文没写到的视觉改动一律不做（见第 8 节）。发现本文有错，停下来改文档并说明，不要悄悄按自己的理解做。

## 1. 目标与范围

**用户反馈**（Windows 桌面版，显示器缩放 100%）：程序界面和编辑区的字体难看，和 Notion 差距大；整体风格不像 Notion 那种浅灰色的优雅。

**目标**：在不换界面技术的前提下，把观感拉到"安静、暖灰、像纸"的方向：

1. 色调从冷蓝灰换成暖灰，蓝色只留给真正的主操作。
2. 字重、字号、行高收敛成一套阶梯，小字不再用粗体。
3. 去掉 Material 的水波纹、阴影层级和 chip 观感。
4. 在 Windows 100% 缩放下，通过实测选出观感最好的字体方案。

**非目标**（不在本次范围）：

- 不改信息架构、布局结构、功能和交互流程；首页不动（用户已定）。
- 不换渲染引擎、不切 Impeller、不改 Flutter 版本（`.fvmrc` 钉 3.47.1）。
- 不追求文字锐利度与 Notion 持平：Flutter 自绘文字只有灰度抗锯齿，没有 ClearType 亚像素渲染，这是引擎限制，只能缓解。要根本解决见 `docs/architecture/ui-gpui-evaluation.md`。
- Web、macOS、Linux、Android 不做专门调优，但色板和排版令牌是全平台共用的，改动后它们必须不变差（跑各自测试即可）。

## 3. 第 0 阶段：先测量，再动手（必做，不改观感）

下面三件事是推断，决定了后面字体方案怎么选。**在 Windows、缩放 100% 的机器上实测**，结果写进本文第 11 节，再开始第 1 阶段。

**H1（待测）：画布里的西文到底用的是哪个字体。** 画布 `TextStyle` 没有字体族，会落到引擎默认字体。中文版 Windows 的系统消息字体是 Microsoft YaHei UI，所以编辑区的英文和数字可能是雅黑的西文字形，而界面是 Segoe UI，两处不一致。
测法：做一个临时调试页（不合入），同一行字 `Mica 知识库 0123 Agent` 在 12/13/14/16/20/30px 下分别用「不指定字体族」「`Segoe UI`」「`Microsoft YaHei UI`」画三遍，截图放大对比字形，判断"不指定"等于哪一个。界面里的 `Text`（走主题）同样测一遍。

**H2（待测）：小字发虚有多少来自非整数位置。** 行高 26.4px 和 12.5px、11.5px 这类字号，可能让基线或字形落在半像素上。
测法：同一段中文在行高 1.65（26.4px）和 1.625（26px）下各截一张 100% 截图，放大到 400% 看相邻行的笔画粗细是否一致。

**H3（待测）：雅黑在灰度抗锯齿下，是否不如思源黑体（Noto Sans SC）。** 雅黑的小字清晰度靠字形微调和 ClearType，Flutter 两样都没有；思源黑体是为不做微调的屏幕设计的。
测法：见第 4.2 节的字体对比页，这一步的产出就是给用户挑选用的截图。

**基线截图**：改动前，在 Windows 100% 下截取并存档下列画面（浅色、深色各一套），放 `docs/plans/assets/ui-refresh/before/`：
登录页、主界面（侧栏 + 一篇含 H1–H3、正文、列表、引用、代码块、表格、待办的中文文档）、斜杠菜单、搜索对话框、设置（外观页）、右键菜单、版本历史对话框。
每个阶段完成后在 `after-pN/` 放同一组截图。**没有前后截图的阶段不算完成。**

## 4. 分阶段清单

阶段之间有先后：0 → 1 → 2 → 3 → 4，第 5 阶段（图标）可选且最后做。每阶段单独提交，提交说明写阶段号。

### 4.1 第 1 阶段：色板换成暖灰（只动令牌）

**改什么**：`lib/ui/theme_tokens.dart` 里 `MicaTokens.light` 和 `dark_` 的取值，按第 5 节的表**逐项照抄**。

1. `TextTokens` 新增第四档 `ghost`（含 `lerp`、构造参数、两套取值）。含义：**不承载信息的字**——输入框占位提示、禁用态文字、纯装饰性的分隔符号。
2. 把现有 96 处 `text.faint` 逐个分类，只把符合下列情形的改成 `text.ghost`，其余保持 `faint`：
   - `hintStyle` / `hintText` 的颜色（含 `inputDecorationTheme.hintStyle`）；
   - 禁用（`onPressed == null`、只读不可操作）控件的文字和图标；
   - 面包屑的 `/` 分隔符、列表项之间的 `·` 之类纯装饰字符；
   - 编辑器空段落的占位提示（"输入 / 唤出命令"这类）。

   **不许**改成 `ghost` 的：时间戳、字数统计、文件大小、路径、快捷键提示、空状态说明、已完成待办的文字。这些是信息，留在 `faint`。拿不准的留在 `faint`。
3. 令牌之外的约 42 处 `Color(0x…)` 字面量：属于灰阶或蓝色强调的，改为读令牌；属于品牌图形（`sign_in_hero.dart`）、头像色板（`api/models.dart`）、状态色、代码高亮的**不动**。逐处在提交说明里列出"改了/保留及原因"。
4. `ColorScheme.fromSeed` 之后的 `copyWith` 映射保持现有对应关系，不新增映射。
5. **实测补充（2026-11-12）**：现有 `_navigationPane`、`_collapsedNavRail` 的背景读的是 `surface.base`，不是 `surface.raised`；只改令牌无法产生下文要求的侧栏与正文底色差。这两处改读 `surface.raised`，仅修正既定背景角色，不改布局。
6. **实测补充（2026-11-12）**：版本历史的只读 `MicaEditor` 漏传当前色板，深色预览仍使用浅色文字和块底。显式传入当前 `MicaTheme` 的 `EditorAppearance`，配浅/深色回归测试；不改版本加载或恢复逻辑。

**测试**：

- `test/theme_tokens_test.dart`：更新钉死的取值；"faint 在四种底色上 ≥4.5:1 且比 muted 浅"这条守护**保留**并必须通过；新增一条"ghost 比 faint 浅，且只允许出现在白名单用途"——后半句用一个源码扫描测试实现：`text.ghost` 的使用点数量登记为基线，新增要改基线并说明。
- `test/workspace_overview_test.dart` 里钉的 `0xFF636C76` 同步更新。
- 深色、浅色各跑一遍现有全部 widget 测试。

**验收**：截图里不再有偏蓝的灰；侧栏与正文区的分界靠底色差而不是靠线（线仍在，第 3 阶段处理）；所有文字对比度见第 5 节表，不低于表中数值。

**不许做**：改状态色、代码高亮色、提示块（alert）的五种强调色、强调蓝的色值；为了"更像 Notion"把 `faint` 调到 4.5:1 以下。

### 4.2 第 2 阶段：字体与排版

分两步，**2a 先出对比图给用户挑，2b 按用户选定的方案落地**。没有用户的选择不许做 2b 的字体族部分；2b 里的字重、字号、行高规则不依赖字体选择，可以先做。

#### 2a 字体对比页（临时，不合入主线）

做一个调试页面，在 Windows 100% 下截图。每个方案画同一块内容：界面小字（12、13、14px 的侧栏项、按钮、菜单项）和编辑区内容（H1 30px、H2 24px、正文 16px 三行中英混排、13px 脚注、行内代码）。

| 方案 | 西文 | 中文 | 说明 |
| --- | --- | --- | --- |
| A（现状） | 不指定 | 现有回退链 | 对照组 |
| B（系统字体显式化） | `Segoe UI` | `Microsoft YaHei UI` | 不增加安装包体积；解决 H1 的不一致 |
| C（系统新字体） | `Segoe UI Variable Text`（仅 Win11 有，回退 `Segoe UI`） | `Microsoft YaHei UI` | 不增体积；Win10 上等于 B |
| D（内置思源） | `Segoe UI` | 内置 `NotoSansSC`（先用现有的常规一档） | Windows 安装包 +8.5 MB；若要粗体还需再加一档字重文件（每档约 +8.5 MB） |

产出：一张拼好的对比图 `docs/plans/assets/ui-refresh/font-compare.png`（浅色、深色各一），加一段不带倾向的说明（每个方案的体积代价）。**交给用户选**，把结论写进第 11 节。

#### 2b 落地

1. **字体族集中在一处**：在 `lib/cjk_fonts.dart`（或新建 `lib/ui/typography.dart`，行数紧就新建）定义 `uiFontFamily`（按平台返回）和现有的 `cjkFontFallback`。`toMaterialTheme()` 的 `ThemeData(fontFamily: …)`、编辑器 `EditorAppearance.applyTo` 的默认字体族，都从这里取。**画布和界面必须解析到同一个西文字体**（H1）。用户在设置里选的"衬线 / 等宽"仍然优先。
2. **字重规则**（Windows 上雅黑只有细体、常规、粗体三档，Segoe UI 没有 500 档：`w500` 实际渲染成常规，`w600` 西文是半粗、中文直接落到粗体）：
   - 字号 **< 16px 一律不用 `w600` 及以上**。小字要强调，用颜色（`primary` 对 `muted`）或底色，不用粗细。
   - 全库只允许三档：`w400`（默认）、`w500`（按钮、选中项、表头——在不支持 500 的字体上等于常规，这是可接受的）、`w600`（仅 ≥16px 的标题）。`w700`、`w800` 清零，例外只有 Markdown 粗体标记本身（`marks.dart`，用户写的 `**粗体**`）。
   - 逐处处理现有 72 处 `w600`：≥16px 的保留；<16px 的改 `w500` 并确认颜色是 `text.primary`。
3. **字号阶梯**：只允许 `11 / 12 / 13 / 14 / 16 / 20 / 24 / 30`，外加两个限定用途的值：`18` 只给编辑器 H4，`26 / 34` 只给登录页大标题。`12.5 → 12` 或 `13`（同一组件内统一）、`11.5 → 11` 或 `12`、`10 → 11`、`15 → 14` 或 `16`、界面里的 `18 → 16` 或 `20`。改字号可能引起布局溢出，每改一类跑对应 widget 测试。
4. **行高取整**：行高像素 =（字号 × 倍数）四舍五入到整数。编辑器有用户字号缩放（`fontScale`），要在缩放**之后**取整：`height = (scaledSize * ratio).round() / scaledSize`。取值见第 6 节。
5. **编辑器样式**（`EditorTheme.styleFor`）按第 6 节表改。H6 保持 `muted` 色。
6. `filledButtonTheme` / `outlinedButtonTheme` / `textButtonTheme` 的 `textStyle` 统一：14px、`w500`，并都带 `fontFamilyFallback`（现在 `outlinedButtonTheme` 漏了）。

**测试**：`flutter test` 全绿；编辑器的行高变化会影响依赖像素坐标的测试（如 `touch_selection_test.dart`、`multitap_select_test.dart` 里的 `Offset(40, 170)` 这类标定值），**按新行高重新标定并在注释里写明算法，不许用放宽断言的方式让它过**。加一条源码扫描测试：`lib/` 下 `fontSize:` 的字面量只能取阶梯内的值，`FontWeight.w700/w800/bold` 只能出现在白名单文件。

**验收**：小字（12–14px）中文不再出现粗体糊成一团；编辑区和侧栏的英文、数字字形一致；400% 放大看相邻行笔画粗细一致。

**不许做**：引入本文没列的字体；为某一处单独写字体族；给文字加 `letterSpacing`（中文加字距会更散，唯一例外是全大写英文小标签可用 0.3–0.5）；用 `FontWeight.w300` 细体。

### 4.3 第 3 阶段：去掉 Material 观感

1. **水波纹**：`toMaterialTheme()` 里设 `splashFactory: NoSplash.splashFactory`、`splashColor` 与 `highlightColor` 为透明、`hoverColor: surface.hover`。全库效果：点击没有扩散动画，悬停是一块浅灰底。
2. **悬停与选中**（列表行、菜单项、侧栏页行、标签页）统一规则：
   - 悬停：底色 `surface.hover`，圆角 6，无边框，无过渡动画或 ≤80ms。
   - 选中：底色 `surface.hover`（同悬停或略深，不用蓝色洗底），文字 `text.primary` + `w500`。**选中态不用强调蓝**，例外见第 4 阶段。
   - 按下：底色比悬停再深一档（`surface.sunken` 上叠加即可），不要水波纹。
3. **阴影与层级**：对话框 `elevation: 12 → 0`，改用 1px `border.normal` 边框 + 一层很轻的阴影（`BoxShadow(color: 0x1A000000, blurRadius: 24, offset: (0, 8))`；深色模式 `0x66000000`）。菜单、弹出层 `elevation: 6 → 0`，同样处理（阴影 `blurRadius: 12, offset: (0, 4)`）。其余 `elevation:` 逐处清零，卡片不要阴影。
4. **圆角**：控件 6、菜单与卡片 8、对话框 12。现有 `controlShape` 8 → 6。不许出现更大的圆角和胶囊形（头像、状态圆点除外）。
5. **分隔线**：51 处 `Divider` / `VerticalDivider` 逐处判断——相邻两块已经有底色差或留白 ≥12px 的，删掉线；确实需要线的，用 `border.subtle`、1px。侧栏与正文之间保留 1px `border.subtle`。
6. **设置页的选项 chip**（字体、主题、语言）：换成分段选择——一组等高按钮，选中项白底（深色用 `surface.overlay`）+ 1px `border.normal` + `text.primary`，未选中项无底无边 + `text.muted`。做成一个共用小组件，`ChoiceChip` 在全库清零。`chipTheme` 保留给仍需要的标签（tag）场景，去掉选中的蓝色洗底。
7. **输入框**：默认 1px `border.normal`、填充 `surface.base`；聚焦时边框 `accent.primary` 1px（现在是 1.5px，改 1px）外加 2px 的 `accent.wash` 外圈；高度统一 36。
8. **按钮**：高度 40 → 32（对话框主操作可 36），水平内边距 12；主按钮（`FilledButton`）每个界面**最多一个**；其余用无底的文字按钮或 1px 边框按钮。
9. **提示气泡**：保持深底浅字，圆角 6、字号 12。
10. **滚动条**：细（6px）、圆角、平时 `border.strong` 40% 透明，悬停变实；不占布局宽度。

**测试**：受影响的 widget 测试里按类型或图标查找的（`find.byType(ChoiceChip)` 等）跟着改；`test/touch_selection_test.dart` 里用 `Icons.format_bold` 定位格式栏的写法，在第 5 阶段之前不受影响。

**验收**：点任何按钮、行、菜单项都没有水波纹；设置页没有胶囊形的 chip；除对话框和弹出菜单外，界面上没有阴影。

**不许做**：自己发明新的组件形态；加入入场、出场动画；用半透明毛玻璃效果。

### 4.4 第 4 阶段：强调蓝的用量收敛

蓝色（`accent.primary`）**只允许**用于：

- 每个界面唯一的主按钮；
- 文本链接、`[[页面链接]]`；
- 光标、文字选区、拖放指示线；
- 输入框聚焦边框；
- 开关（Switch）和复选框的选中态；
- 协作者光标各自的颜色不受此限。

**改为中性色**的：侧栏当前页的选中底色（蓝洗底 → `surface.hover`）、标签页选中态（如有蓝色下划线或蓝字 → `text.primary` + 底色）、菜单选中项、搜索结果当前项、设置页选中的选项、图标按钮的激活态（用 `surface.hover` 底 + `text.primary`，不用蓝色图标）。

做法：全库搜 `accent.primary`、`accent.wash`、`colorScheme.primary`、`secondaryContainer`，逐处对照上面的白名单，不在白名单里的改中性。在提交说明里给出改动前后的使用点数量。

**验收**：打开一篇普通文档，不做任何操作时，屏幕上的蓝色只有链接（如果文档里有）和光标。

### 4.5 第 5 阶段（可选，最后做，需用户点头）：图标换成细线风格

Material 图标偏粗偏圆，约 340 处。方向：换成 1.5px 线宽的线性图标集（候选 `lucide_icons_flutter`，ISC 许可；实施前核对许可证、包体积和 Dart 版本兼容，并登记进第三方声明）。

做法**必须**是：新建 `lib/ui/mica_icons.dart`，以语义命名集中映射（`MicaIcons.search`、`MicaIcons.pageAdd`…），全库只引用 `MicaIcons`，不直接引用任何图标包。先做映射层（值仍指向 Material 图标，零观感变化，单独提交），再换底层图标集（第二个提交）。找不到对应图标的保留 Material 的 outlined 变体，不要自己画。

图标尺寸：侧栏和菜单 16，工具栏 18，颜色 `text.muted`，悬停 `text.primary`。编辑器画布里用 `icon.fontFamily` 直接画字形的地方（`render.dart`、`block_renderers.dart`、`font_warmup.dart`）要同步，并保证字体预热仍然覆盖新图标字体。

这一阶段改动面最大、对测试影响最大（很多测试按 `Icons.xxx` 查找）。**没有用户明确同意不要开工。**
