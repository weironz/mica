# 项目约定

## 文件命名
所有设计页面用两位数序号前缀命名，按产品使用流程排序，不带「Mica」前缀：
`01 登录引导.dc.html`、`02 工作区总览.dc.html`、`03 首页+侧栏.dc.html`…

新建页面时：
- 判断它在流程中的位置，插到合适的序号；后面的文件依次重新编号。
- 不确定放哪就追加到末尾。

宿主的页面列表按「最近编辑时间」排序，不是按文件名——需要恢复成序号顺序时，从最大序号到最小序号依次触碰文件（move 到 tmp/ 再 move 回来），最后 01 最新即排在最上。

## 视觉规范
- 灰阶只用 EditorTheme 三档：`#24292F` 正文 / `#57606A` 次要 / `#9AA4AF` 弱化；强调色 `#2563EB`；边框 `#EEF1F5`（内部分隔）、`#E5E9F0`（容器）。不要再引入 slate 系（#94A3B8、#B4BECE 等）。
- 字号阶梯：12 / 13 / 14 / 16 / 20 / 26 / 34，不要出现 13.5、14.5、15.5 之类的碎值（存量页面逐步收敛）。
- 圆角：8（控件）/ 14（卡片）/ 16（弹窗）。
- 空状态与故障态一律「说清发生了什么 + 给一个下一步」，不写「出错了」。

## 产品事实（Mica）
- 仓库 weironz/mica，见 github.md。
- **有实时协作，该画就画**：工作区成员、4 个可分配角色（`admin` / `editor` /
  `commenter` / `viewer`，见 `workspaces.rs` 的 `normalize_member_role`）、presence
  在线状态与实时光标（`PresenceUser` / `_PresenceBar`）、按角色分享、评论线程与
  回复/解决（`comments.rs` 五个端点）——全部已上线。
  〔2026-08-26 之前这一行写的是**反的**：「没有实时协作功能，不要出现团队成员等入口」。
  照字面执行会删掉成员、角色、presence、评论四套东西，而设计稿自己就自相矛盾——10 画了
  带头像/邮箱/角色的成员列表，11 就叫「实时协作」还画了 presence 条。来历留着，是因为
  一条**被改正过的**错误前提，比一条从没错过的规则更容易被人再写回去。〕
- **两个世界始终并存**：登录后云端与本地工作区同时列出、可随时切换
  （`_workspaceEntries` 合并两边），设置面板的 tab 随世界增减。用户已明确拍板
  「本地云不合并成单视角」。
  〔原文是「登录时选定本地/云端模式，进入后只有一个视角，不再分云端/本地标签」——
  在那个前提下，13 工作区迁移这一屏根本不存在。〕
- 「已同步」状态不显示任何指示（见 cloud/sync_status.dart）；只有同步中、离线两态可见。
