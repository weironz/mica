# 页面标题:从「视图属性」改成「文档的一部分」

> 状态:**P1 基本完成**(读侧统一),P2/P3 未开始。2026-08-27 用户提出,同日成稿并实施。
> P1 里还差两块,都在 §5.4 和 §5.5 里写明:Ctrl+C 整页(**未拍板**)、本地离线模式的单页导出。
> 「五条代价」而不是标题写的四条 —— §5.5 是做的过程中长出来的,没有合并进前面几条。
> 这份文档的作用是让每一条代价在动手**之前**就有具体答案 —— 上一件同量级的事
> (侧栏多选)没这么做,做到一半冒出三个意外,其中一个改了实现方式。

## 1. 问题

页面标题今天是 `views.name`(Postgres 列),**不在文档里**。于是「页面变成文本」的每一个
出口都得自己把名字和正文拼起来,而实际上**大多数出口没拼**。

2026-08-27 逐条实测(不是读文档 —— 文档在这件事上是错的,见 §6):

| 出口 | 正文里有标题吗 |
| --- | --- |
| 单页 `.md` 导出 | ❌ |
| 单页 ZIP 导出 | ❌(名字只在文件名) |
| 工作区 ZIP 导出 | ❌(名字在文件名 + `manifest.json`) |
| 工作区 / 全部工作区扁平 markdown | ✅ `# <页名>` |
| 单页 HTML 导出 | ✅ |
| 菜单「复制页面内容」 | ❌ |
| 编辑器里 Ctrl+A / Ctrl+C 整页 | ❌(标题是编辑器之外的 TextField) |
| **大纲面板** | ❌ **页面自己的标题不在自己的目录里** |
| MCP `mica_read_document` | ❌ |

用户的应对是**关掉「显示页面标题」、在正文手写一个 H2**,于是每建一页要做两件事,
而且改名之后两处会对不上。

## 2. 为什么不是「导出时注入」

第一版方案是:在产出文件的出口把 `# <页名>` 拼进正文。被用户否掉,理由成立:

- **违背所见即所得** —— 编辑时看到的和任何一个输出都不是同一份内容。
- **出口是开放集合** —— 复制、Ctrl+C、大纲、MCP,以及以后每一个新出口,都要记得拼。
  忘一个就是一个静默的不一致,而 §6 证明这种遗忘**已经发生过**。
- 它也有双表示,只是换了位置:**存着的正文 ≠ 序列化出来的正文**。区别仅在于它是推导的
  (不会漂移),代价是每个消费者都得记得推导。

## 3. 为什么也不是「注入正文第一行」

第二版是:新建页面时真的往正文插一个 `# 名` 块。也被否掉:

- **强加结构** —— 有人第一行就是正文,不想要标题。这一版要么逼他加,要么这页没名字。
  (Bear / iA Writer 就是这个模型,「第一行是什么标题就是什么」经常很难看。)
- 若名字和标题块**两份都存**,改名必然漂移 —— `lessons.md#1` 那条双表示。

## 4. 方案:标题存在文档的 **root 块**上

两个参照系都是这么做的,**不是**往正文注入:

- **AFFiNE**(源码已读,`blocksuite/affine/blocks/root/src/adapters/markdown.ts`):标题是
  root 块的 `props.title`,markdown 适配器导出时合成一个 `heading depth 1`。
- **Notion**:标题是页面属性,markdown 导出前置一个 H1。

Mica 已经有这个位置:文档有 root 块(`snapshot.root_block_id`),它**今天就在存
`front_matter`**,而且 `content_text_from_doc` 明确把它排除在正文之外(注释原话:
*"empty-text blocks — page root, images — dropped"*)。

**所以:标题写进 `root.data['title']`,和 `front_matter` 并列。**

同时满足两条互相拉扯的要求:

| | 导出注入 | 正文注入 | **root 块** |
| --- | --- | --- | --- |
| 所有入口看到同一份内容 | ❌ | ✅ | ✅ |
| 正文第一行可以是任何东西 | ✅ | ❌ | ✅ |
| 改名不漂移 | ✅ | ❌(两份都存时) | ✅ |

`views.name` 随之变成**投影** —— 和 `content_text` / `link_targets` 同一个模式:
一个函数是唯一生产者,与文档写入同一事务共写。这是仓库里第三个实例,不是新架构。

### 4.1 不做全量回填迁移

**取值规则:`title = root.data['title'] ?? views.name`。**

于是**不需要**为几千个存量文档各写一次 CRDT。存量页保持现状,第一次有人改标题时才把它
写进文档。代价是过渡期内两种页面并存 —— 但取值只有一条规则,不存在「哪个赢」的歧义。

### 4.2 协作编辑标题仍然是后写覆盖,不要吹成 CRDT 合并

`data` 是块上的一个 JSON map,写一个字符串是**整值替换**,不是字符级合并。所以两个人同时
改标题仍然是 LWW —— **和今天一样,不更好也不更坏**。

〔成稿过程中我一度把这条写成「白捡一个好处:标题走 CRDT 了会合并」,是错的。要真的合并,
标题得放 root 的 `text`(Y.Text),那会改变 `content_text` 的投影语义、以及渲染器对
「root 块没有文本」的假设 —— 不在本方案里。〕

## 5. 五条代价,每条一个决定

### 5.1 ⚠️ 服务端改名会打死整页评论锚点 —— **需要一个新原语**

这是本方案唯一的硬门槛,而且**是实测出来的,不是推理**。`comments.rs:423`:

> *A rewritten document: identical text, brand-new text objects — **what every REST/MCP
> write** and every version restore does to a document.*

也就是说**今天任何服务端写文档都走 `set_blocks` 全量重建**。侧栏 F2 改名、MCP
`mica_rename` 如果去写文档,那一页的评论锚点全部变成孤儿。

〔我在写这份文档的过程中先猜了一句「定向更新 root 块,正文块不动,应该不受影响」,
**猜错了**。这条路径今天不存在。〕

**决定:新增一个只写 root 块 `data` 的定向 yrs 写入原语**(`set_root_data(key, value)`),
不经过 `set_blocks`。

**验收测试(必须先写、必须验过有牙)**:一页带评论 → 走新原语改标题 → 锚点仍解析到原
位置。`comments.rs` 已有 `rewrite()` 与锚点断言,照它的形状写;把新原语换成 `set_blocks`
应当当场变红。

### 5.2 文件夹没有文档

文件夹的名字仍然是 `views.name` 上的普通字段。**决定:接受这条不对称,不给文件夹造文档。**
理由:文件夹是容器不是内容,给它造一个空文档只为放一个名字,是为了对称而增加的一层。
取值函数对文件夹直接返回 `views.name`。

### 5.3 存量 / 导入的页没有标题

由 §4.1 的回落规则覆盖,**不批量注入**。一次导入几百页不该触发几百次文档写入。

### 5.4 过渡期:谁先谁后

**决定:分三期,每期自己可用,不留半态。**

- **P1 —— 读侧统一。** 加取值函数;所有出口改成走它:单页 `.md` / 单页 ZIP / 工作区 ZIP /
  复制页面内容 / 大纲。`root.data['title']` 此时还没有任何写入者,一律回落到 `views.name`
  —— **P1 单独上线就修好了 §1 那张表的大部分**,而且不动权威归属。
  ✅ **2026-08-27 完成**(`fe181a0` + `34637fc`)—— **除了 Ctrl+C 整页,见 §5.5**。
  本地(离线)模式的单页导出/复制**也还没做**,它要给 FFI 加参数并重新生成桥接
  (工具链在本机是齐的:`flutter_rust_bridge_codegen 2.12.0`,与 pubspec/生成文件同号)。
- **P2 —— 写侧改向。** 编辑器标题字段写 `root.data['title']`(经 5.1 的新原语);
  `views.name` 变成投影,在文档写入处共写。F2 / MCP `mica_rename` 改走同一条路。
- **P3 —— 导入与 round-trip。** 导入时把 manifest/文件名的标题写进 root;导出侧
  `with_page_title` 与导入侧 `strip_leading_h1` 配对,export→import 字节稳定(CLAUDE.md #4)。

**MCP 读取仍然不带标题**,而且这不是遗漏:`GET .../export/markdown` 与 `PATCH` 共用一个
handler,读带上标题的话,agent 的「读 → 改 → 整篇替换」会把它写成正文里真实的 heading,
**每往返一轮多一层**。P3 若要让 MCP 读带标题,必须同时让 PATCH 对称剥离,并配一条
「读→写→读 三次不变」的测试。

### 5.5 Ctrl+C 整页:**未拍板**,它和其它出口不是一类

其它三处都是「把页面变成一份要交出去的文本」。**Ctrl+C 复制的是选区** —— 而标题不在选区里,
因为它压根不在编辑器的文档里。要让它带上标题,得同时做四件事:

1. 把页名传进编辑器(它现在不知道页面叫什么);
2. 加一个「选区是否覆盖整篇」的判据;
3. **plain 和 HTML 两种剪贴板格式都要改** —— `_copySelection` 的注释明写着两者
   「must not diverge」;
4. **剪切(`_cutSelection`)必须不带** —— 标题剪不掉。

代价不只是这四处,而是它引入一个**不连续**:全选复制带标题,少选一个字符就不带。这种
「差一个字符行为就变」的东西,用起来比缺失更让人困惑。

**而且已经有一个正好干这件事的入口**:菜单「复制页面内容」,一次点击,现在带标题。

**留到 P2 之后再看**:标题搬进 root 块之后,如果编辑器把它渲染成文档的一部分,它**有可能**
自然进入选区 —— 但那需要标题也进编辑器的选区模型,**不是 P2 自动带来的**。所以这里不写
「P2 会解决」,只写「P2 之后重新评估」。

## 6. 顺带:两处过期文档必须一起修

本次调查里被文档误导过一次,教训进 `lessons.md`:

- `docs/export-import.md`:「Page content 是 `# <title>\n\n<body>`」—— **假的**,实测导出的
  zip 里 `.md` 第一行就是正文。
- `crates/interchange/src/import.rs:115`:「their name round-trips through the `# {name}` H1
  the export prepends」—— **假的**,而且和**同一个文件 219 行**的设计声明直接矛盾(那里写的是
  "our own export writes the name into the file name, **never into the text**")。

一个文件里两句话互相矛盾、其中一句还进了另一份文档,是这次多花了几个来回的直接原因。

## 7. 这份方案推翻了什么

`import.rs:219` 那段是一个**刻意的产品决定**:

> *a page's name is a property of the page, not a line inside it*

本方案**不推翻它** —— 标题仍然是页面的属性,只是这个属性从 Postgres 列搬进了文档的 root
块,于是每个读文档的人都能看见它。「不是正文里的一行」这条继续成立:root 块不是正文块,
正文第一行仍然可以是任何东西。
